# 经验沉淀与新人学习闭环

## 目标

把调度员、班长、设备和公辅专业在真实班次中的判断，沉淀成下一班可以检索、练习和复核的工作方法。系统不把“自动学习”理解为模型自行改规则，而是把事实、决定、结果和适用边界先保存，再经过专业审核后进入学习库。

## 一条案例如何产生

| 环节 | 现场动作 | 系统留下的内容 | 放行条件 |
| --- | --- | --- | --- |
| 班后补事实 | 补齐原计划、平台建议、实际回传和未采纳原因 | 班次编号、输入快照、方案版本、执行偏差 | Historian/MES未回传时实际值留空，不允许补写估计值 |
| 专业审核 | 生产、设备、安环或经营专业确认事实和判断 | 审核人、时间、意见、适用工况和禁用条件 | 事实完整、来源可追溯、责任专业明确 |
| 生成学习卡 | 改写成“先看什么、怎么判断、什么时候停用、找谁确认” | 场景、关键变量、判断顺序、错误示例、检查问题 | 至少一名主责专业审核；涉及设备或安环时必须会签 |
| 复用与回测 | 新员工完成案例题，再用新班次复核是否仍适用 | 学习人、完成时间、答题结果、复用班次、偏差 | 新班次事实重新核对；不能绕过当前审批和现场规程 |

## 网页上的操作

进入“执行复盘”，找到“经验沉淀与新人学习”：

1. 选择液氨趋紧、公辅波动或压机弱信号案例。
2. 点击“载入案例”，查看当时事实、专家判断、可复用条件和禁止直接套用的边界。
3. 对待审核案例点击“提交专业审核”。审核完成前，“生成学习卡”保持锁定。
4. 审核通过后点击“生成学习卡”，再由新员工完成本张学习卡。

企业上线时，案例事实和审核记录由飞书多维表格承载，专业会签由飞书审批承载，学习任务由飞书 Task 承载，Aily 只允许检索已经审核的知识源。

## 建议的飞书多维表格字段

`case_id`、`shift_id`、`scenario`、`source_snapshot`、`plan_version`、`human_plan`、`platform_plan`、`actual_value`、`adoption_status`、`reject_reason`、`external_factors`、`reviewer_production`、`reviewer_equipment`、`reviewer_hse`、`applicable_conditions`、`stop_conditions`、`rule_version`、`knowledge_status`、`last_reviewed_at`。

`knowledge_status` 至少分为：`待补事实`、`待专业审核`、`可生成学习卡`、`已发布学习卡`、`暂停复用`。每次状态变化都保留前一版本和修改人。

## 企业验收建议

- 每个已发布案例都能追到一个真实班次或企业批准的仿真班次。
- 学习卡必须有来源、适用条件、禁用条件、责任岗位和当前规则版本。
- 待审核案例不能被 Aily 检索为确定性答案，不能进入规则候选集。
- 新员工完成学习后，必须在下一次班前会或跟班复核中确认是否适用。
- 规则更新采用人工发布、版本可回滚；单个班次或单个学习结果不会自动改变生产规则。
