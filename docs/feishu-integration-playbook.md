# 飞书功能接入说明

## 定位

飞书在本方案中不是展示入口，而是调度建议从“算法结果”进入“班组执行”的组织系统。平台把每次合成氨负荷调整拆成六类飞书对象：互动卡片、审批、任务、多维表格、事件回调和 Aily 问答。

## 互动卡片

互动卡片发送到合成氨当班调度群，内容包含目标负荷、风险指数、模型置信度、约束解释、预计收益和回写范围。按钮保留三类动作：采纳并发起审批、要求复核、驳回并填写原因。按钮事件进入后端队列，以 `shift_id + proposal_id + action_id` 做幂等键。

## 审批

审批定义建议命名为 `ammonia_load_adjustment`。低风险建议由班长确认，高风险建议增加调度主管复核和安环知会。审批通过后只允许回写 MES 班次计划、交接班摘要和复盘表，不写 DCS/SIS 控制参数。

## 多维表格

多维表格作为调度知识库的事实层，至少包含班次、场景、目标负荷、风险指数、预计收益、采纳状态、未采纳原因、执行偏差、班长备注和复盘结论。字段样例见 `data/feishu_dispatch_review_template.csv`。

本轮已按样例创建飞书 Base 原型：`https://www.feishu.cn/base/QzENbAkl1aYQGds8dBacqu6Inue`。

## 飞书任务

每个被采纳方案自动生成一个跟踪任务，负责人包括调度员、班长和设备工程师。任务检查项包括确认 DCS historian 实际负荷、记录未采纳原因、班后复盘收益归因。

决赛提交任务清单原型：`https://applink.feishu.cn/client/todo/task_list?guid=2ab6c357-dfeb-4f75-9aa3-781dc7ac7244`。企业试点时同一机制用于跟踪“采纳方案执行监督”“班后复盘补录”“周度规则校准”等任务。

## 事件回调

建议订阅 `card.action.trigger`、`approval.instance.status_changed`、`bitable.record.changed` 等事件。回调入口必须做签名校验、重放保护和幂等入库。低置信度、数据延迟、安环红线接近时，事件处理只保留记录，不触发后续回写。

## 飞书 AI 调度问答

飞书 AI 只读取经过授权的产供销全线事实表、MES订单、DCS摘要、设备趋势、调度复盘库和经批准的处置规则。回答固定包含五部分：结论、当前数值、安全边界、事实来源、责任人与复核时间。无可追溯来源时不输出确定性现场结论，而是创建人工复核任务。

典型问题包括：为什么不建议硝酸满负荷、液氨涨价后该保谁、压机弱信号继续恶化怎么办。回答可继续生成班组卡片、执行任务或复盘草稿；涉及高风险负荷调整时仍必须走班长/主管审批。

## 当班操作台映射

- 当班事件队列映射飞书卡片与责任人任务，按P1/P2/P3标记处置优先级。
- 产供销全线事实表映射Base记录和ERP/MES来源，支撑“保、稳、降、限、停、询价外采”判断。
- 方案执行监督映射审批状态、MES目标负荷、DCS实际负荷和班末效果复核。
- 数据新鲜度超过15分钟时，飞书AI停止自动重算并转人工确认。
