# 企业导师展示清单

## 展示目标

用 5 分钟让导师看清楚一件事：我们做的不是一个只会给出负荷数字的模型，而是一名站在生产运行管理层的调控师。它把产供销取舍、稳定生产预警、班组确认、飞书流转和班后复盘放在同一条可追溯链路上。

展示时始终把三个边界说清楚：页面里的价格、库存、负荷和设备趋势是验收样例；平台不写 DCS/SIS；没有企业 Historian 回传时，实际值和收益不填写。

## 导师追问时的回答

### 1. 价格从哪里来？

公开来源只提供参考和交叉核验；液氨、硝酸及下游产品的执行价来自企业 ERP、销售报价或采购结算版本。企业上线时由经营人员确认价格、区域、单位、含税/运费口径、生效时间和版本。

### 2. 这和 DCS 有什么区别？

DCS 负责装置局部控制、顺控、报警和联锁；我们处理的是跨装置的生产运行决策，例如下游需求变化后是否减负荷、液氨优先供给谁、什么时候需要专业会签。平台只提出可追溯方案，不写 DCS/SIS。

### 3. 你们能不能证明已经节约了多少钱？

目前不能把验收样例贡献值称为实际收益。只有建议被采纳、现场执行完成、Historian 回传实际数据，并完成同口径原计划对照和班后归因后，才进入收益统计。

### 4. AI 会不会替代调度员？

我们把它定位为调度员的数字助手：先汇总事实、校核约束、比较方案，再交给班长和专业人员确认。它的价值是减少信息整理和经验差异，责任仍在企业现行审批和操作制度中。

### 5. 飞书现在是真接入还是展示？

Task v2普通任务、多维表格样例和在线方案稿已经验证；互动卡片、审批状态机、自动拆分四岗位任务和事件回传属于原型或待企业授权能力。我们在材料中分开标注，避免把设计能力说成已经上线。

## 现场不要说

- 不说“已经接入云图实时数据”；应说“当前为可复现验收样例，接口按 30/60/90 天试点接入”。
- 不说“模型保证最优”；应说“在当前输入、规则和约束下比较候选方案，企业阈值由专业人员确认”。
- 不说“自动控制装置”；应说“生产运行管理层的只读建议与协同执行工具”。
- 不把“岗位接令”说成“现场执行”，不把“相对外售分配贡献”说成“已实现收益”。

## 展示结束后的材料顺序

1. 先给导师看网页现场操作和下载的证据包。
2. 再打开 06 号主方案，解释业务主线和 30/60/90 天试点。
3. 导师追问飞书时打开 07 号模块说明，展示对象、权限和状态边界。
4. 导师追问验收时打开 08 号附件，展示证据链、四岗位动作单和必过项。
5. 最后给出 GitHub 仓库，说明源码、样例数据、接口矩阵和材料均可复核。
