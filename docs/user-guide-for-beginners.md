# 氨智领航调控师平台使用说明

## 这套平台是做什么的

这不是一个直接操作阀门的控制系统，也不是只显示曲线的看板。它模拟一名合成氨生产调度员的工作：把订单、液氨库存、下游产品、能源、公辅和设备趋势放在同一份班次事实里，比较几种可行方案，再把需要谁确认、谁执行、什么时候复核写清楚。

第一次接触合成氨的人，可以把它理解成一张“工厂运行取舍地图”：

- 上游合成氨产出的是液氨；
- 液氨可以进入尿素溶液、复合肥、硝酸、联碱等下游，也可以外售；
- 液氨不是无限的，订单、价格、库存、能源和设备状态会同时变化；
- 平台要回答的不是“产得越多越好”，而是“在安全和连续生产前提下，这一班液氨怎样分配更合适”。

当前网页使用的是可复现的验收样例，目的是展示工作流程。它没有接入云图现场的实时数据，也不会写入 DCS 或 SIS。页面里出现的价格、库存、负荷、设备趋势和收益均不能直接当作企业实际值。

## 第一次使用的最短路径

1. 打开平台：`http://127.0.0.1:4173/`。
2. 点击顶部场景“稳氨”。这是最适合第一次看的平稳样例。
3. 先看中间深色的“当前调度建议”：读懂目标负荷、预计产氨、有效至和回滚触发。
4. 点击“产供销平衡”，查看液氨期初库存、预计产氨、各去向分配和期末安全余量。
5. 点击“联网读取官方参考”，查看来源卡片。公开行情只是参考，真正参与经济比较的执行价格仍要企业经营人员确认。
6. 点击“稳产预警”，查看压缩机趋势。它是提前复核提示，不是 DCS 报警。
7. 点击“执行复盘”，依次查看卡片、审批、岗位接令和班末复盘。接令不等于现场已经执行。
8. 点击“导出当前方案证据包”，下载 JSON 文件，查看本次判断用了哪些输入和门禁。

如果只剩 5 分钟，按这个顺序展示即可：`稳氨` → `当班态势` → `联网读取官方参考` → `保供` → `产供销平衡` → `护机` → `稳产预警` → `执行复盘` → `导出证据包`。

## 页面组件说明

### 1. 顶部状态区

| 组件 | 它是什么 | 你应该怎么读 | 可以做什么 |
| --- | --- | --- | --- |
| 云图合成氨 · 班次调度工作台 | 页面身份 | 说明当前页面服务的是合成氨生产运行管理 | 不需要操作 |
| 白班 D-01 和时钟 | 当前演练班次 | 说明建议属于哪一个班次、何时生成 | 不代表企业真实班次号 |
| 演练模式 / 不写 DCS/SIS | 系统边界 | 说明这是一层建议和协同原型，不会直接控制装置 | 展示时要主动说清楚 |
| 行情样例需核价 | 经济口径状态 | 说明当前价格还没有经过经营人员确认 | 未确认前不要把经济排序当执行方案 |

### 2. 场景按钮

场景按钮不是“启动装置”的按钮，而是沙盘回放按钮。点击以后，平台把一组条件带入计算，便于观察在不同矛盾下会怎么做。

| 场景 | 代表的现场问题 | 重点看什么 |
| --- | --- | --- |
| 稳氨 | 装置总体平稳，希望连续、经济运行 | 建议负荷、库存余量、回滚条件 |
| 保供 | 下游订单压力高或液氨库存偏紧 | 液氨分给谁、刚性订单是否优先、期末库存是否安全 |
| 护机 | 压缩机或合成塔健康下降 | 负荷是否应该收敛、设备专业是否需要会签 |
| 错峰 | 能源或蒸汽成本出现高价窗口 | 什么时候少产、什么时候补库存，是否影响刚性订单 |

### 3. 工作台视图

视图按钮只是切换关注范围，不会删除数据。

- **当班态势**：第一次打开先看这里。它把当前建议、四个关键指标、液氨平衡、事件队列和压机趋势放在一起。
- **产供销平衡**：回答液氨从哪里来、要分给谁、分完之后还剩多少。这里最适合讲云图企业的产业链协同。
- **稳产预警**：回答装置是否出现需要提前复核的变化。这里看趋势和责任岗位，不把提示直接当报警。
- **执行复盘**：回答建议有没有经过班长确认、岗位是否接令、现场是否回传、班末是否复盘。
- **依据与接入**：回答数据来自哪个系统，企业上线时如何接 MES、ERP、IoT、DCS 摘要、APC、设备软件和 Historian。

### 4. 演练沙盘输入和滑块

左侧“演练沙盘输入”是做情景推演的。每个数字不是现场当前真实测量值，而是一个样例条件。

| 输入 | 通俗解释 | 数值变大通常表示什么 |
| --- | --- | --- |
| 下游订单压力 | 下游客户要货紧不紧 | 订单更紧，需要更重视交付和液氨分配 |
| 能源/蒸汽成本 | 公用工程对生产的成本压力 | 高价时要考虑错峰，但不能破坏安全和刚性订单 |
| 压缩机/合成塔健康 | 关键设备当前可承受程度 | 变低时要保守运行并安排专业复核 |
| 液氨库存水位 | 罐区中可调配液氨的相对余量 | 变低时要保护安全库存，重新分配去向 |
| 低碳能源可用 | 低碳电力或能源窗口是否充足 | 影响错峰和能耗比较，不直接决定产量 |
| 液氨市场价 | 经济比较中的液氨价格样例 | 只有经过经营确认才可以作为执行价 |
| 硝酸行情趋势 | 硝酸产品市场方向样例 | 变差时需要比较减负荷、停运代价和其他去向 |
| 压机趋势证据强度 | 压缩机多变量异常趋势的样例强度 | 变高时优先设备复核，极高时触发停算演练 |

建议一次只调整一个滑块。调完后观察三个地方：当前调度建议是否变化、约束解释是否变化、事件队列是否出现新的责任岗位。

### 5. 经营行情闸门

“联网读取官方参考”不是把网上价格直接写进生产计划。它做三件事：读取已登记的公开参考源、显示来源和更新时间、告诉使用者哪些价格仍需企业确认。

“确认本轮样例行情”是演示中的经营确认动作。企业正式上线时，确认人应核对：产品、区域、单位、含税/运费口径、生效时间、来源版本和确认人。没有这些条件，平台沿用上一有效版本，并冻结新的经济排序。

因此，网页里看到“官方参考已更新”时，正确理解是“参考资料更新了”；看到“行情样例已确认”时，才表示本轮样例可以进入演练计算。两者不是一回事。

### 6. 当前调度建议和四个 KPI

中间深色卡片是平台的主要输出。阅读顺序是：

1. **标题**：这次建议要解决什么问题，例如稳定合成回路、平衡液氨库存和下游消纳。
2. **目标负荷**：合成回路建议运行在什么负荷水平。它是目标，不是已执行的实际负荷。
3. **预计产氨**：按照样例负荷推算的 24 小时产量，不是 Historian 回传的实际产量。
4. **有效至**：建议多长时间后需要重新核对数据。
5. **回滚触发**：偏差太大、关键数据失效或现场拒绝时，停止沿用当前建议，回到最近批准方案和现场规程。

四个 KPI 的含义：

- 目标负荷：平台建议合成回路做到多少；
- 未来 24 小时预计产氨：样例条件下的估算量；
- 24 小时分配贡献：不同液氨去向的相对比较值，不是实际利润；
- 约束状态：当前是否越过硬约束、还有多少事项需要专业复核。

### 7. 24 小时液氨平衡

这是最重要的业务账之一。基本关系是：

`期末可用量 = 期初可用量 + 预计产氨 + 外采到货 - 各去向计划分配`

页面把五类事实分开显示：期初可用量、预计产氨、外采到货、计划分配和期末可用量。下面的颜色带表示期末库存相对于安全上下限的位置。

看这块时不要只问“能不能多生产”，还要问：多生产的液氨给谁、是否挤占刚性订单、期末是否低于安全下限、如果某个下游异常是否需要重算。

### 8. 事件队列和压机趋势证据

事件队列是“要人处理的事项”，不是系统自动替人执行。P1 通常代表需要优先响应，P2 代表当班复核，P3 代表持续观察。每个事件会显示来源、影响、责任人和截止时间。

压机趋势证据通常包括：

- 轴振动：机器振动是否持续变大；
- 轴位移：转子位置是否偏离正常范围；
- 防喘振裕度：压缩机离喘振风险还剩多少余量；
- 轴承温度：轴承是否持续升温。

单个变量轻微变化不一定代表事故。平台关注的是趋势是否持续、多变量是否同向变化、是否接近关注线，然后把复核任务交给设备专业。DCS 报警、SIS 联锁和现场规程仍然优先。

### 9. 产供销全线事实表和经济账本

这部分是调度的“取舍桌”。它比较不同下游去向：当前需求、计划分配、单位液氨相对贡献、连续运行代价和当前动作。

这里的“分配贡献”表示在同一批输入条件下，一个去向相对液氨外售基准多带来的贡献比较。它不是财务确认利润，也不能证明平台已经帮企业节约了多少钱。真实收益必须拿同一时刻的人工原计划和实际执行结果做对照。

### 10. 规则方案比选、接口层和排产草案

- **规则方案比选**：把不同方案的目标和代价摊开，不让使用者只看到一个无法解释的答案。
- **APC/RTO 对接层**：说明平台未来如何把批准后的班次目标交给已有的先进控制和实时优化系统；不是重新建设 DCS。
- **接口字段矩阵**：说明每个字段的唯一事实源、读写方向、更新时间、质量码、责任岗位和失败处理。
- **班次排产草案**：把 24 小时建议拆成装置和时间段，便于班前会和交接班讨论。

### 11. 跨装置调度动作单和执行监督

动作单把一个“调度决定”拆成可以被岗位接住的任务，例如合成回路、硝酸装置、罐区与液氨去向、热电与公辅。每行都有当前事实、调整建议、节奏、责任岗位和执行前置条件。

正确的操作顺序是：

1. 调度员核对输入和方案；
2. 班长确认目标负荷、有效期和回滚条件；
3. 相关岗位接令并复核前置条件；
4. 现场按规程执行；
5. MES 或 Historian 回传实际负荷、库存、能耗和异常；
6. 班末比较建议与实际，记录采纳或未采纳原因。

页面的“接令”复选框只记录责任岗位已看到和复核，不表示现场阀位或负荷已经变化。

### 12. 飞书班组协同

飞书在这套方案里不是装饰性链接，而是承接协作动作的工作入口：

- **互动卡片**：把当前事实、建议、风险和确认按钮发给相关人员；
- **审批**：班长、调度主管或设备/热电专业进行会签；
- **Task 任务**：把事件检查项、责任人、截止时间和复核要求变成待办；
- **多维表格 Base**：沉淀班次输入、建议、采纳状态、执行偏差和复盘结论；
- **智能问答 / Aily**：让新手用自然语言追问依据、术语和下一步；
- **事件回传**：把审批、接令、任务完成和复盘结果写回审计链。

当前页面的飞书按钮主要生成本地草稿或演示状态。企业上线时还要由管理员配置自建应用权限、审批定义、目标群、Aily 知识源、事件订阅和回调地址。

### 13. 数字调度长问答

问答区不是开放式闲聊，而是把调度问题按四层回答：

1. 当前事实是什么；
2. 为什么得出这个判断；
3. 受到哪些安全、设备、库存或价格边界约束；
4. 下一步由哪个岗位在什么时间完成什么动作。

例如“压机趋势继续恶化怎么办”，正确答案不会直接说“自动减负荷”，而是先看趋势证据，再安排设备复核；达到设定的停算条件时冻结新建议，转人工和现场规程。

### 14. 岗位视图和三条底线

同一份班次事实会按岗位改变关注重点：调度员看跨装置分配，班长看确认和回滚，设备人员看趋势和点检，安环人员看红线和降级。

“调度三条底线”可以概括为：先安全、再保证流程连续、最后才是在特殊情况下做停运或降负荷取舍。任何经济收益都不能覆盖设备保护、安环红线和现场规程。

### 15. 其他容易被忽略的组件

- **调控师指令**：左侧按钮集中放置重算、生成卡片、生成审批、保存复盘和导出证据包。建议先重算，再生成草稿；当前按钮不会直接写入生产系统。
- **约束解释**：把安全库存、设备健康、能源、公辅和负荷变化速度等限制列出来。红色通常代表硬约束，黄色代表需要专业复核，绿色代表当前满足条件。
- **收益归因**：把订单满足、液氨分配、能耗、库存占用和异常等因素拆开，避免把所有变化都算成平台收益。班末需要补齐人工原计划和实际结果后再统计。
- **班次排产草案**：把 24 小时建议拆成装置和时间段，便于班前会和交接班讨论。它是讨论稿，未经班长确认和岗位接令不能当现场计划。
- **数据接口优先级**：说明订单、MES、IoT、DCS 摘要、APC、设备软件和 Historian 哪些先接，谁是唯一事实源。
- **数据新鲜度**：说明每类数据距离上次更新多久。数据超时、质量码异常或事实源不一致时，平台应降低置信度，必要时停止新建议。
- **飞书链接**：页面底部链接通往调度复盘库、执行任务清单、验收任务和在线方案文档。当前链接用于演示；企业正式使用时需换成企业自建应用和授权后的地址。

## 常见术语

| 术语 | 用大白话理解 |
| --- | --- |
| DCS | 装置控制系统，负责局部调节、顺控和报警，本平台不写入 |
| SIS | 安全仪表系统，负责联锁和保护，本平台不绕过 |
| APC / RTO | 先进控制和实时优化层，把批准的目标转成受约束的控制目标 |
| MES | 生产计划和执行系统，记录生产计划、实际完成和班次事实 |
| ERP | 经营和财务系统，提供订单、价格、结算等口径 |
| Historian | 生产历史数据库，保存真实点位、负荷、库存、能耗和设备趋势 |
| 负荷 | 装置当前开到多大程度，页面中的目标负荷不是实际负荷 |
| 液氨库存 | 罐区可供下游或外售的液氨余量 |
| 影子运行 | 平台先观察和给建议，现场仍用原流程，等对比可靠后再小范围执行 |
| 安全闸门 | 发现数据或现场风险不满足条件时，停止新建议并转人工 |
| 接令 | 岗位已看到并复核任务，不等于现场已经执行 |

## 看到哪些状态时该怎么做

- **行情样例需核价**：可以看公开参考，但不要采纳新的经济排序；等经营人员确认。
- **待专业复核**：不要只由调度员自行确认，把动作交给设备、热电、罐区或安环专业。
- **数据完整度下降**：先查事实源、时间戳和质量码；必要时回到上一有效方案。
- **安全闸门锁定**：平台停止生成新目标，按现场规程和人工调度处理。
- **待 Historian 回传**：只能说“建议已发出或接令已记录”，不能说“已经完成”。
- **证据完整度不足**：先补行情、订单、库存或设备事实，再谈经济收益。

## 企业正式试点时需要补什么

1. 确定订单、价格、库存、生产负荷、设备趋势和能源数据的唯一事实源。
2. 先做 30 天只读校核，再做 60 天旁路回放，最后做 90 天小闭环验证。
3. 由企业确认产品、区域、单位、税费、运费、结算时间和价格版本。
4. 与企业确定 DCS、SIS、APC、MES、ERP、Historian 和飞书的读写边界。
5. 用真实班次比较人工原计划、平台建议和实际执行，形成采纳/未采纳原因库。
6. 只有完成安全、设备、生产和经营专业验收后，才扩大到更多装置和班组。
