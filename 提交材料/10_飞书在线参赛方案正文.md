## 二、方案成果展示【必须包含】

### 1. 命题场景描述、问题描述及痛点说明

#### 1.1 为什么硬件领先之后，调度仍有优化空间

云图的超大型合成氨装置已经具备先进的 DCS、生产信息化、机组监测和自动化控制基础。继续提高某一个局部回路的控制精度，并不能自动解决生产运行管理中的跨系统取舍。真正困难的是：液氨有限时，尿素、硝酸、复合肥、联碱配套和液氨外售怎样分；下游需求、能源条件、市场价格或设备状态变化时，哪些装置应该维持、降负荷、错峰或停运；一次正确判断怎样被记录并传给下一班。

本方案把 AI 放在生产运行管理层，而不是放进 DCS/SIS 控制层。它连接经营、调度、生产、设备、公辅、罐区和班组，为现场人员提供“可复算的事实、可解释的建议、可追责的协同和可审核的经验”。

#### 1.2 企业导师指出的四类真实矛盾

| 真实场景 | 目前依赖人工完成的工作 | 对企业的影响 |
| --- | --- | --- |
| 产供销重排 | 调度长从订单、库存、MES、价格和下游需求中逐项汇总，再判断液氨去向和装置负荷 | 信息链长，行情和需求变化后容易错过调整窗口 |
| 跨装置联动 | 下游异常、公辅受限或库存变化时，人工判断合成氨、下游、罐区与能源系统的调整顺序 | DCS 只能处理局部控制，跨装置协调高度依赖成熟调度长 |
| 设备弱信号 | 操作员观察振动、轴位移、防喘振裕度、温度等趋势，凭经验判断是否需要升级 | 新员工可能把持续偏离看成正常波动，预警时机容易丢失 |
| 经验传承 | 班后口头复盘、交接记录和个人经验分散保存 | 成熟调度长培养周期长，未采纳原因和适用条件难以沉淀 |

#### 1.3 本方案每天回答三个现场问题

1. **现在最值得优先保障哪一个液氨去向？**  
   在库存、订单、下游需求、能源和产品经济性同时变化时，给出可复核的分配建议。

2. **当前波动会不会影响连续生产？**  
   识别跨装置影响，给出负荷调整顺序、保持条件、撤销条件和需要会签的专业岗位。

3. **这次判断以后能不能复用？**  
   保存事实、依据、人工取舍、执行结果和未采纳原因，经专业审核后进入企业案例库。

### 2. 方案优势/创新点

#### 2.1 一句话亮点

本方案交付的不是一个只显示数据的看板，也不是一个绕过现场人员的自动控制器，而是一名能够“把账算清、把依据说清、把任务交给责任岗位、监督结果回传、把审核经验留下来”的数字调度长。

#### 2.2 Before / After

| Before：当前人工调度方式 | After：氨智领航调控师 |
| --- | --- |
| 多套系统各自显示数据，调度长人工汇总 | 形成统一班次事实表，每个字段保留来源、时间、单位和质量状态 |
| 依靠个人经验比较液氨去向 | 先做物料与安全校核，再比较边际贡献、订单、停开损失和连续运行代价 |
| 建议通过电话、群消息逐层传递 | 飞书卡片、审批、Task 和动作单明确责任人、截止时间、版本与回执 |
| 接令、执行和实际效果容易混在一起 | 接令只证明收到方案，实际值必须由 Historian 或企业认可的事实源回传 |
| 班后经验散落在口头和交接记录中 | 复盘案例经专业审核后生成带适用条件和禁用条件的学习卡 |
| 系统上线前缺少可验证过程 | 先做影子运行，把平台建议与人工原计划在同一输入快照下并排验收 |

#### 2.3 五项核心创新

**创新一：从单装置优化转向产供销全线联动。**  
把液氨库存、下游需求、订单、能源、设备和价格放入同一个班次决策，直接回答“液氨给谁、负荷怎样联动、是否外采或停运评估”。

**创新二：经济取舍可复算、可解释。**  
平台区分相对外售分配贡献、固定成本吸收、停开损失、违约风险和液氨机会成本。即使产品售价低于完全成本，也能解释继续运行是否仍覆盖合理增量成本。

**创新三：AI 不越过安全边界。**  
确定性的物料守恒、安全库存、公辅余量和设备边界交给规则与计算引擎；低置信度、数据失效、口径冲突或接近安全边界时，系统停止生成可执行建议并转人工。

**创新四：每条建议都有证据包和退出条件。**  
输入快照、行情版本、物料平衡、约束门禁、方案版本、动作单、接令状态、飞书流转和审计事件可以导出复核。

**创新五：学习对象是经过审核的企业案例。**  
系统不会把每一个班次自动当作正确答案。采纳、驳回、人工修改、实际偏差和外部影响必须由生产、设备、安环和经营专业审核后才能复用。

### 3. 具体方案说明（突出 AI 能力）

#### 3.1 完整业务闭环

**数据接入 → 质量校核 → 液氨平衡 → 安全与连续生产约束 → 候选方案比较 → 人工确认 → 飞书协同 → 岗位接令 → 执行回传 → 班后复盘 → 专业审核 → 知识复用。**

平台由五层组成：

1. **事实层：** 汇总 MES、IoT、生产历史数据库、热电 APC、压机软件、关键机组和经营数据。
2. **计算层：** 处理液氨守恒、库存安全线、公辅余量、装置能力和设备趋势证据。
3. **建议层：** 比较继续运行、降负荷、转供、外采、外售、错峰或停运评估等候选动作。
4. **协同层：** 使用飞书卡片、审批、Task、多维表格和事件回传组织人工确认与责任闭环。
5. **学习层：** 把经审核的班次案例、适用条件、禁用条件和规则版本沉淀为企业知识资产。

#### 3.2 混合智能架构与完成状态

本方案采用“硬约束计算 + 候选方案比较 + 多变量趋势识别 + 知识问答 + 人工会签”的混合智能方式。确定性的物料与安全问题不交给大模型猜测，AI 主要承担跨系统事实整理、候选方案生成、趋势关联、解释和知识检索。

| AI / 计算环节 | 解决的问题 | 当前交付状态 |
| --- | --- | --- |
| 物料与安全约束引擎 | 液氨守恒、库存、公辅与设备边界 | 可复算验收样例已实现 |
| 候选方案生成与解释 | 比较保供、稳氨、护机、错峰四类取舍 | 规则化交互原型已实现 |
| 多变量弱信号识别 | 联合观察轴振、轴位移、防喘振裕度和温度 | 历史回放样例已实现，企业阈值待标定 |
| 机理模型 / PINN 校准 | 提高变负荷工况模型适应性 | 候选研究路线，尚未使用企业数据校准 |
| Aily 知识问答 | 基于审核案例解释依据、撤销条件和历史处置 | 知识结构与回答约束已设计，待授权知识源 |
| 审核式经验学习 | 把复盘结果转为案例与新人学习卡 | 治理流程和网页原型已实现 |

#### 3.3 当班态势与四个生产场景

网页顶部提供“稳氨、保供、护机、错峰”四个场景入口：

- **稳氨：** 装置总体稳定，重点保持连续生产并兼顾库存和下游消纳。
- **保供：** 液氨偏紧或订单压力增大，重点处理产品优先级、库存安全线、外采和下游降负荷。
- **护机：** 关键设备趋势偏离，重点处理专业复核、负荷限制、风险升级和停算门槛。
- **错峰：** 蒸汽、电力或公辅成本变化，重点处理能源约束、错峰窗口和对产量库存的影响。

#### 3.4 经营行情闸门：防止网络价格误导生产

平台可以读取国家统计局、交易所和商务部公开信息，也可以接入企业 ERP、销售采购和结算价格。公开信息只用于趋势参考，不能直接替代液氨或下游产品的企业执行价。

价格进入经济比较前必须确认产品、区域、单位、含税/运费口径、生效时间、确认人和版本。未确认、过期或口径冲突时，平台沿用上一有效版本并冻结新的经济排序。网页不会因“联网成功”就把公开价格自动变成现场成本。

#### 3.5 24 小时液氨平衡与典型班次结果卡

平衡模块把期初库存、预计产氨、外采、各下游用氨和期末库存放到一张账上，回答“液氨够不够、分完以后是否跌破安全下限”。

**验收样例 NH3-D01-001：**

- 期初可用液氨：1,357 吨
- 未来 24 小时预计产氨：1,734 吨
- 外采：0 吨
- 计划分配：2,115 吨
- 预测期末库存：976 吨
- 企业验收样例安全库存：780 吨
- 安全余量：196 吨，可支撑约 36 小时

物料校核：**1,357 + 1,734 + 0 - 2,115 = 976 吨。**

在同一价格版本和输入快照下，复合肥、尿素、纯碱、硝酸和液氨外售的相对外售分配贡献样例合计为 **769,488 元/24 小时**。结果用于比较候选分配，不代表已经实现的企业收益。

#### 3.6 产供销事实表与经济取舍

事实表把产品、订单优先级、需求、计划负荷、液氨消耗、价格版本、非氨变动成本、物流包装、停开损失和外售机会成本放在一起。

平台先检查安全、连续生产、物料守恒和刚性订单，再比较：

- 产品是否覆盖原料、蒸汽、电力、包装和物流等增量成本；
- 有限液氨供给不同下游时的替代贡献；
- 停车重启产生的废料、时间、人员和物料损失；
- 继续生产对固定成本的吸收；
- 外采、外售和违约风险。

固定成本吸收作为管理解释单列，不与增量贡献混为一谈。最终输出包括优先保障、维持、降负荷、转供、外采暂缓或停运评估的理由和撤销条件。

#### 3.7 设备弱信号与专业复核

设备模块联合观察压缩机负荷、轴振、轴位移、防喘振裕度、轴承温度、持续时间和数据质量。平台不直接给出“停车”指令，而是回答：

- 哪个变量正在变化，持续多久；
- 数据是否可信，是否需要核对冗余点位；
- 先检查哪些现场现象；
- 何时需要设备、工艺或仪表专业复核；
- 哪些条件成立后停止生成新建议并转现场规程。

处置分为一般提示、专业会签和演练停算线。达到登记条件时才升级专业会签；停算时停止新目标、经济排序、动作单和审批，保持最近批准方案。

#### 3.8 跨装置调度动作单

当方案需要联动时，平台把一个调度建议拆分为合成主操、下游主操、罐区/调度和公辅调度四类岗位动作，写明：

- 班次编号和方案版本；
- 目标负荷与升降负荷节奏；
- 前置条件、保持条件和撤销条件；
- 有效期、责任岗位和异常退回路径。

四个岗位全部接令后才允许进入执行跟踪。“接令”只表示收到有效方案并确认责任，不代表现场已经执行。实际负荷、库存和能耗必须来自 Historian、MES 或企业认可的事实源。

#### 3.10 证据包、执行监督与影子运行

每次建议可以生成一份证据包，保存输入快照、行情版本、物料平衡、约束门禁、方案版本、撤销条件、跨装置动作单、岗位接令、飞书流转状态和审计事件。评委可从网页直接导出 JSON 复核。

试点首先采用影子运行：冻结同一历史班次输入，把平台建议与人工原计划并排比较。有效班次必须具有冻结的原计划、合格输入、可追溯建议、完整人工确认、真实执行回传和班后复盘。未执行方案可以用于流程验收，但不进入效果统计。

#### 3.11 经验沉淀与新人学习

每个案例拆成六项：发生了什么、使用了哪些数据、平台建议是什么、人工为什么采纳或驳回、实际结果如何、以后什么条件下可以复用。

学习卡必须带来源班次、审核人、适用工况、禁用条件和规则版本。新人可以按液氨趋紧、下游降负荷、公辅受限、压缩机弱信号和异常停运取舍等场景训练。系统先展示事实和选项，让新人做出判断，再展示专家复盘。

### 4. 方案价值

#### 4.1 对企业三大挑战的直接回应

| 企业挑战 | 本方案的回应 | 企业形成的长期资产 |
| --- | --- | --- |
| 调度寻优难 | 用同一输入快照完成液氨守恒、硬约束校核、候选方案比较和解释 | 可复算的班次方案、经济测算口径和规则版本 |
| 指挥效率低 | 通过飞书卡片、审批、Task 和动作单组织多岗位确认与回执 | 有责任人、有时限、有版本、有结果的指挥链 |
| 知识传承难 | 把事实、判断、采纳/驳回、执行结果和适用条件审核入库 | 企业自己的调度案例、禁用条件和新人学习卡 |

#### 4.2 可量化验收指标

| 指标 | 定义稿口径 | 试点目标建议 |
| --- | --- | --- |
| 数据可用率 | 新鲜度窗口内且质量合格的必需记录数 / 应到必需记录数 | 不低于 98% |
| 物料平衡残差 | 期初 + 产量 + 外采 - 分配 - 期末的绝对残差占比 | 不高于 1.5% |
| 快照重算 P95 | 输入快照冻结至方案、约束证据和测算明细完成的 95 分位耗时 | 不高于 120 秒 |
| 调度决策中位耗时缩短 | 同类场景试点中位耗时相对基线的缩短比例 | 不低于 30% |
| 高优订单满足率 | 按企业冻结的订单口径计算 | 由企业基线确认 |
| 设备趋势提示提前量 | 提示到专业确认或异常升级之间的时间 | 由设备专业定义 |
| 复盘完整率 | 事实、判断、结果和审核结论完整的有效班次比例 | 由企业基线确认 |

以上是试点定义稿，不代表当前已经取得现场效果。30 天数据校核后，由企业冻结字段、分母、时间范围、基线期和排除项。

#### 4.3 30/60/90 天企业试点路线

- **30 天：先把账对上。**  
  接订单导出、MES 班次计划、罐区历史摘要和飞书协同记录，校核字段、单位、时间基准、质量码和责任岗位，全程只读。

- **60 天：把建议放到历史现场回放。**  
  扩展生产历史数据库、公辅能源、设备和机组只读数据，回放产供销重排、公辅波动和设备趋势三类场景，与人工原方案并排比较。

- **90 天：在企业批准范围内做条件受控验证。**  
  覆盖不少于 30 个有效班次。只有安全、数据真实性、可复算、专业会签和动作单门禁全部通过，才进入小范围执行验证。

### 1. 幕后故事和花絮（可选）

项目从企业导师的一句话开始收缩方向：“最紧迫的是产供销协同，系统之间仍像信息孤岛。”此后方案不再平均展示所有 AI 能力，而是把主线聚焦为液氨有限条件下的跨装置调度，把设备弱信号作为稳产辅助，把经验审核与新人学习作为支撑底座。

### 3. 最终说明

演示中的价格、库存、负荷和设备趋势均为可复现样例，不代表企业实时数据。真实生产效果必须经过数据校核、历史旁路回放、专业会签和企业批准的受控试点后计算。

本方案的目标不是让 AI 替现场人员做出未经确认的动作，而是让企业调度判断更快被看见、更容易被复核、更容易形成责任闭环，并让下一位调度员能够站在前人的有效经验上工作。
